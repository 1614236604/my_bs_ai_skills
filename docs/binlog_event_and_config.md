# Binlog 事件系统与配置

## 概述

Binlog 事件系统为 MAC 和 RLC 层提供高性能二进制日志能力。系统通过**事件类型**和**严重级别**两个维度对日志进行分类，并提供灵活的过滤机制，使开发者能够在运行时按需开启或关闭特定类别的日志输出。

## 事件类型

系统定义了一组事件类型，覆盖 MAC 和 RLC 层的关键处理路径（如调度、HARQ、链路自适应、承载数据传输等）。每个事件类型拥有唯一的数字 ID 和对应的配置键名。

其中 GENERAL 事件为特殊类型：它不受事件掩码过滤，始终可记录（仅受严重级别约束）。

## 严重级别

系统采用 8 级严重度模型（从高到低）：EMERGENCY、ALERT、CRITICAL、ERROR、WARN、NOTICE、INFO、DEBUG。

初始化时设置严重级别阈值，仅 severity ≤ 阈值的事件被记录。阈值可在运行时动态调整。

## 过滤机制

事件写入前经过三层过滤，任一层拒绝则跳过（零开销）：

1. **调用点有效性检查** — 调用点必须已在元数据中注册
2. **Severity 检查** — 事件严重级别 ≤ 会话阈值
3. **Event Mask 检查** — 事件掩码位向量中对应位为 1

### 事件掩码（EventMasker）

- 内部为位向量，每个事件类型占 1 bit
- 通过检查对应位判断事件是否启用
- GENERAL 事件不经过掩码检查，始终记录（只要通过 severity 检查）

## 配置方式

### 事件类型过滤

通过环境变量在启动前配置，控制哪些事件类型被启用：

- 指定事件类型的配置键名，以管道符（`|`）分隔，启用特定事件
- 设置为 `all` 启用所有事件
- 不设置时，所有 TRACE 级事件被屏蔽，仅 GENERAL 事件通过

### Severity 阈值

通过 OAM Logger 配置传入，在会话初始化时设置。运行时可动态调整。

## 日志记录方式

系统提供两类日志记录接口：

- **通用日志**：按严重级别（DEBUG / INFO / WARN / ERROR）记录，归属 GENERAL 事件类型，不受事件掩码过滤
- **事件追踪日志**：以 DEBUG 级别记录，需指定事件类型，受事件掩码和严重级别双重过滤

典型使用模式：通用日志用于记录聚合统计和异常信息；事件追踪日志用于记录特定处理路径的逐步细节，可通过事件开关按需启用。
