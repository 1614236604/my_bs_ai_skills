# 用户主动纠错

## 场景

修复 tc 编码 bug 时，初始方案将 `encodeTc()` 放在 `nrMacUeSimContext.h` 中，导致 Builder 为了调用这个通用编码方法而被迫 include 了 UeSimContext 头文件，产生了不必要的模块耦合。

## 用户预期

通用的编解码方法（如 `encodeTc`）的放置位置不应迫使无关模块引入不必要的依赖。如果一个方法本身与某个模块的职责无关，就不应该定义在该模块的头文件中。正确做法是将编码提前到数据生产侧完成，让消费侧只接收已经编码好的值，从根本上消除对编码方法的依赖。

## 需求

放置工具方法时要考虑引用链的影响：如果方法 A 定义在模块 X 的头文件中，那么所有需要调用 A 的模块都会被迫依赖 X。当 A 的功能与 X 的职责不相关时，应将 A 移到更合适的位置，或重新设计数据流使消费侧不需要调用 A。
